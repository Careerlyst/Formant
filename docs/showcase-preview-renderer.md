# Showcase preview renderer deployment

PDF and website previews use the isolated `showcase-renderer` container. It is a private service, not a public API. Deploy it behind an authenticated private ingress and set `SHOWCASE_RENDERER_TOKEN` (at least 32 random characters) both there and as a Supabase Edge Function secret. Set `SHOWCASE_RENDERER_URL` to the private HTTPS ingress URL.

The worker runs as the unprivileged Playwright user. PDF files are rendered by Poppler in an ephemeral directory. Generated PDF and website WebP derivatives, plus manually uploaded JPG/PNG/WebP previews, are resized and composited with the official symbol-only Formant SVG from `assets/formant-symbol.svg`. No watermark text is drawn. Website capture accepts only HTTPS port 443, resolves every requested hostname, rejects any non-public DNS answer, pins the request to a validated address, validates every redirect and subresource, caps request count/bytes/time, blocks service workers and non-GET requests, and returns only a screenshot and page title/description.

The authenticated `showcase-preview-upload` function also calls the private renderer's `POST /watermark/image` route. The route requires the same bearer token as the PDF and website routes, accepts only JPEG/PNG/WebP under 8 MB, verifies the decoded image format, and returns a logo-composited WebP derivative capped at 3 MB. The Edge Function keeps the unchanged source image in a separate private Storage object and stores the derivative at its own unique immutable path. Only the derivative receives a media row, with `is_public_preview=false`; the source object has no media row and cannot be resolved through the public image function or RPC. Staff must separately review and approve the derivative.

The hosting environment must additionally enforce outbound network controls: deny loopback, private, link-local, multicast, and cloud metadata destinations at the network/firewall layer; permit only DNS and outbound public HTTPS needed for screenshots. Do not expose the worker ingress publicly, mount credentials, or run it with a service-role key. The Edge Function is the only caller and performs staff authorization and the private Storage/database work.

For this logo-watermark update, rebuild/redeploy the private renderer with the included symbol asset, then redeploy the updated `showcase-preview-upload` and `showcase-preview-generate` functions with JWT verification enabled. The upload function uses the same `SHOWCASE_RENDERER_URL` and `SHOWCASE_RENDERER_TOKEN` already required for generation. No database migration or bucket-policy change is required. Deploy the frontend separately to remove its former visible text overlay. Existing stored preview objects are immutable and are not changed by this release; create new derivatives through the updated workflow, inspect them, and repeat human review/approval before publication.

Apply the local migration `20261014100000_showcase_preview_generation.sql` to the intended environment before enabling the Edge Function. This migration is not applied to production by this change. Deploy the renderer, configure both secrets, apply the reviewed migration, deploy only `showcase-preview-generate`, then test with synthetic draft records. Generated image rows are always inserted with `is_public_preview=false`; staff must separately review them and update the existing explicit preview approval workflow.

Operational limits: source PDFs up to 15 MB and 12 pages, at most 3 MB per derivative; website captures use the public HTTPS top-level viewport, up to 80 network requests / 30 MB / 25 seconds, and one screenshot. PDF source documents stay in the private `showcase-media` bucket.
